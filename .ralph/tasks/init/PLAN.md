# Plan: init — Distributed Cache Task Runner

## Summary

Build a CLI tool (`dcache`) that skips re-running verification tasks (lint, typecheck, etc.) when source inputs haven't changed. It hashes relevant files, checks a local cache, and only runs the command on a cache miss. Supports two modes: **glob mode** (user provides file patterns) and **nx mode** (auto-resolves files from the Nx project graph).

The project is greenfield — everything is scaffolded from scratch as an Nx integrated monorepo with bun as the package manager.

## Approach

### Workspace setup: Manual scaffold

The research identified that `--preset=ts` generates a workspaces-based layout (not what the spec wants). Instead of fighting generator output, we'll **manually scaffold** the root config files (`package.json`, `nx.json`, `tsconfig.base.json`, `.eslintrc.json`, `.gitignore`) and then use `nx g @nx/js:lib` to generate each library project with the correct structure. This gives us full control over the traditional integrated layout (`libs/`, `apps/`, `project.json` per project, path aliases).

### Architecture

Six libraries in `libs/` + one thin app in `apps/dcache/`:

| Library | Tag | Dependencies | Purpose |
|---------|-----|-------------|---------|
| `config` | `scope:core` | none | Logger, lock-file detection, config loading |
| `hasher` | `scope:core` | config | Streaming SHA-256 file hashing, combined hash |
| `cache` | `scope:core` | config | CacheProvider interface, filesystem JSON cache |
| `runner` | `scope:core` | none | child_process.spawn wrapper, output capture |
| `nx-integration` | `scope:core` | config | Nx project graph, BFS dep resolution, file collection |
| `cli` | `scope:cli` | all core libs | Arg parsing, `run` and `clear` commands |
| `apps/dcache` | `scope:app` | cli | Thin binary entry point with shebang |

### Key decisions

1. **ESM throughout** — `"type": "module"` in root package.json, all imports use ESM
2. **`@nx/js:tsc` for builds** — standard Nx TypeScript compilation
3. **Vitest for tests** — via `@nx/vite` integration
4. **`node:crypto` for hashing** — built-in, no external dependency needed
5. **`fast-glob` for file globbing** — only production dependency
6. **`@nx/devkit` as peer dep** — nx-integration doesn't bundle Nx; consumers provide it
7. **Atomic cache writes** — temp file + `fs.rename()` to prevent corruption
8. **Cache path** — `node_modules/.cache/dcache/<2-char-prefix>/<hash>.json`

### Risks / Open questions

1. **Nx generator compatibility** — `@nx/js:lib` flags may differ across Nx versions. If generation fails, fall back to manual file creation.
2. **ESM + shebang** — the built `main.js` needs both `#!/usr/bin/env node` and proper ESM. TypeScript strips shebangs during compilation, so we may need a post-build step or use `tsup` for the app target.
3. **Bun lockfile detection** — `lock-file.ts` needs to handle `bun.lock` (bun's binary lockfile format was introduced in later versions; bun 1.3.8 uses `bun.lockb`).
